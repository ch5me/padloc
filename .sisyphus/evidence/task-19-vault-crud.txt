# Task 19 Evidence — Vault CRUD

## Implementation Status

### Vault CRUD Operations (packages/core/src/server.ts)

All four vault CRUD operations are implemented and wired through the Cloudflare Worker:

| Operation | Method | Line | Authz Check |
|-----------|--------|------|-------------|
| Create | `createVault()` | 1501 | `_requireAuth()`, org admin check |
| Read | `getVault()` | 1398 | `_requireAuth()`, owner/org member check |
| Update | `updateVault()` | 1425 | `_requireAuth()`, canWrite check, revision check |
| Delete | `deleteVault()` | 1551 | `_requireAuth()`, org admin check |

### Key Security Properties

1. **Encrypted payload handling**: Server stores `encryptedData` as opaque blob — no decryption server-side.
2. **Authorization**: `getVault` checks `vault.owner === account.id` for private vaults and `org.canRead(vault, account)` for shared vaults. Unauthorized access returns `NOT_FOUND`.
3. **Revision continuity**: `updateVault` rejects stale revisions with `OUTDATED_REVISION` error, preventing lost updates from concurrent clients.
4. **Idempotency**: Worker transport layer (`packages/worker/src/transport.ts`) uses `IdempotencyStore` (KV-backed) with SHA-256 body hash to detect and replay duplicate requests.

### D1 Storage Fix

The D1Storage `save` method was fixed to use raw SQL `INSERT ... ON CONFLICT(id) DO UPDATE` instead of Drizzle's `onConflictDoUpdate`, which generates invalid SQL for D1's SQLite (`ON CONFLICT("id")` doesn't match the PRIMARY KEY constraint). Denormalized columns (email, created_at, etc.) are extracted from the raw JSON for indexed lookups.

### Test File
