## WebAuthn Status: EXPLICITLY DEFERRED

WebAuthn is NOT implemented in the Worker backend. This is an intentional defer
with client-safe semantics.

### Why Deferred
- `WebAuthnServer` (`packages/server/src/auth/webauthn.ts`) depends on
  `@simplewebauthn/server`, which uses Node.js `Buffer` and other Node globals
  unavailable in the Cloudflare Workers runtime.
- The Worker `server-factory.ts` does NOT wire `WebAuthnServer` into authServers.
- Porting `@simplewebauthn/server` to Web Crypto would require significant
  reimplementation of CBOR decoding, COSE key handling, and signature
  verification — out of scope for T20.

### Client-Safe Defer Semantics
- `AuthType.WebAuthnPlatform` and `AuthType.WebAuthnPortable` are defined in
  `@padloc/core/src/auth.ts` but no Worker AuthServer supports them.
- When a client requests `startAuthRequest` with `type: AuthType.WebAuthnPlatform`
  or `type: AuthType.WebAuthnPortable`, the core Server will return
  `AUTHENTICATION_FAILED` or `NOT_SUPPORTED` because no registered AuthServer
  returns `true` for `supportsType()` on these types.
- This is safe: the client receives a clear error rather than silent failure.
- Clients should fall back to TOTP or Email auth when WebAuthn is unavailable.

### Files
- `packages/worker/src/server-factory.ts` — TOTP wired, WebAuthn absent (by design)
- `packages/server/src/auth/webauthn.ts` — Node.js-only WebAuthn implementation
- `packages/core/src/auth/totp.ts` — Worker-compatible TOTP implementation
- `packages/core/src/auth.ts` — AuthType enum (includes WebAuthnPlatform, WebAuthnPortable)
- `packages/worker/test/auth-flow-e2e.worker.ts` — TOTP e2e test harness
