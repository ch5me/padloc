# T15 — R2 Attachment Lifecycle Evidence

## Task
Implement R2AttachmentStorage in packages/worker/src/attachments/r2.ts per ADR-006.

## Implementation

### File: packages/worker/src/attachments/r2.ts

**R2AttachmentStorage** — Cloudflare Workers R2-backed AttachmentStorage.

Key design decisions:
- Object key scheme: `att/<vault_id>/<attachment_id>` (ADR-006)
- Upload: D1 INSERT first → R2 PUT second. Rollback D1 on R2 failure (up to 3 retries).
- Delete: R2 DELETE first → D1 DELETE second. Orphan recorded to `orphan_log` on D1 failure.
- Download: D1 SELECT first → R2 GET second.
- Hash: SHA-256 hex stored in D1 metadata and R2 customMetadata.
- Size cap: 25 MB hard cap (`MAX_ATTACHMENT_SIZE`). Rejected before any I/O.
- Signed URL threshold: 5 MB (`SIGNED_URL_THRESHOLD`). 15 min TTL.
- Orphan reasons: `put_rollback_failed`, `delete_d1_failed`, `confirm_d1_failed`, `delete_all_d1_failed`.

**Exports:**
- `R2AttachmentStorage` — class implementing `AttachmentStorage`
- `R2AttachmentStorageConfig` — `{ bucket: R2Bucket, db: D1Database }`
- `MAX_ATTACHMENT_SIZE` — 25 MB
- `SIGNED_URL_THRESHOLD` — 5 MB
- `SIGNED_URL_TTL_MS` — 15 min

**Extra methods (beyond AttachmentStorage):**
- `createUploadUrl(vault, id, size, contentType)` → `{ uploadUrl, r2Key }` — signed R2 PUT URL for direct-to-R2 large file upload
- `confirmUpload(vault, id, size, hash, ownerAccountId, contentType)` — D1 metadata confirm after client direct upload
- `createDownloadUrl(vault, id)` → signed R2 GET URL for direct-from-R2 download
- `verify(vault, id)` → integrity check via custom metadata hash or re-computed hash

**No fs/S3 SDK imports. Workers runtime R2Bucket API only.**

## Partial Failure Handling

| Scenario | D1 INSERT | R2 PUT | Result | Action |
|----------|-----------|--------|--------|--------|
| Upload fail | ❌ fail | — | No row, no R2 | Client retries |
| Upload fail | ✅ pass | ❌ fail | D1 row, no R2 object | D1 rollback (up to 3x), then orphan logged |

| Scenario | R2 DELETE | D1 DELETE | Result | Action |
|----------|-----------|-----------|--------|--------|
| Delete fail | ❌ fail | — | R2 intact, D1 intact | Client retries |
| Delete fail | ✅ pass | ❌ fail | R2 clean, D1 row stale | Orphan recorded |
